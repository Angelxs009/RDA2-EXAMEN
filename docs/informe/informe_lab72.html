Introducción

Una aplicación móvil se juzga, antes que por su lógica, por cómo se ve y cómo se lee. Material Design 3, conocido como Material You, propone que la interfaz no sea un objeto estático sino un sistema que se adapta a la persona: a partir del fondo de pantalla del usuario, Android 12 (API 31) y posteriores extraen una paleta tonal y la ofrecen a las aplicaciones como color dinámico (Google, s. f.-a). Este laboratorio aplica esa idea a la aplicación EcoTrip 2026, construida en el examen práctico anterior, con tres cambios: activar y verificar el esquema de color dinámico, sustituir la fuente del sistema por Poppins mediante Google Fonts descargables, y estrenar una pantalla con TopAppBar y FloatingActionButton que reaccionen a los roles de color del sistema.

El informe documenta cada fase, muestra la evidencia en un emulador con Android 16 (API 36) con dos fondos de pantalla distintos, mide el contraste resultante frente a los umbrales de accesibilidad WCAG y cierra con conclusiones y recomendaciones.

Objetivos

1. Configurar el esquema de color dinámico (dynamicColorScheme) para que la aplicación se armonice con el entorno del usuario.

2. Integrar una fuente de Google Fonts en Type.kt sin incluir archivos binarios en el APK.

3. Implementar componentes Material 3 (TopAppBar y FloatingActionButton) que consuman los roles de color del tema.

4. Explicar cómo el colorScheme influye en la accesibilidad, con mediciones propias.

Marco teórico

Color dinámico. En Jetpack Compose, dynamicLightColorScheme y dynamicDarkColorScheme devuelven un ColorScheme generado a partir del fondo de pantalla del dispositivo (Android Developers, s. f.-a). El esquema no es un color suelto: es un conjunto de roles emparejados (primary con onPrimary, primaryContainer con onPrimaryContainer, etc.) cuyos tonos Material calcula para mantener una relación de luminosidad predecible entre el fondo y su contenido (Google, s. f.-b). Por eso, si el código elige siempre el par de roles correcto, el contraste se conserva aunque la paleta cambie por completo.

Fuentes descargables. La biblioteca ui-text-google-fonts permite declarar una GoogleFont y un GoogleFont.Provider apuntando a Google Play Services, que descarga y cachea la tipografía bajo demanda. El proveedor se autentica con un arreglo de certificados (font_certs.xml), lo que evita empaquetar archivos TTF en la aplicación (Android Developers, s. f.-b).

Accesibilidad del color. Las Pautas de Accesibilidad para el Contenido Web (WCAG) 2.2 exigen una relación de contraste mínima de 4,5:1 para texto normal y de 3:1 para texto grande y componentes de interfaz (criterios 1.4.3 y 1.4.11, nivel AA) (World Wide Web Consortium [W3C], 2023). Aunque nacieron para la web, Android las adopta como referencia en sus guías de accesibilidad (Android Developers, s. f.-c).

Desarrollo

Adaptaciones respecto a la guía

La guía está escrita para el proyecto «SafePass 2026». El repositorio del grupo contiene EcoTrip 2026, por lo que se aplicaron los mismos pasos con los nombres reales: el paquete es com.example.myapplication y la función de tema es MyApplicationTheme (en lugar de SafePass2026Theme). El texto de la pantalla de prueba se conservó tal como lo pide la guía.

Fase 1. Dependencias y certificados

Se añadió la biblioteca androidx.compose.ui:ui-text-google-fonts:1.7.0 al catálogo de versiones (libs.versions.toml) y se referenció desde app/build.gradle.kts; el proyecto usa el BOM de Compose 2024.09.03, que alinea esta biblioteca con el resto de módulos de Compose. El proyecto no incluía font_certs.xml, de modo que se creó app/src/main/res/values/font_certs.xml con los certificados de desarrollo y producción de Google Play Services, copiados del archivo de pruebas oficial del repositorio de AndroidX (The Android Open Source Project, 2022).

Fase 2. Tipografía Poppins

En Type.kt se definió el proveedor, la GoogleFont("Poppins") y una FontFamily con los pesos Normal, Medium, SemiBold y Bold. A diferencia de la guía, que solo sobrescribe titleLarge y bodyLarge, se aplicó Poppins a toda la jerarquía de Typography copiando los estilos por defecto de Material 3 con .copy(fontFamily = …); así, los campos del formulario, las etiquetas y los títulos de EcoTrip también cambian de fuente y la aplicación no mezcla dos familias. titleLarge (Bold, 22 sp) y bodyLarge (Normal, 16 sp) conservan exactamente los valores de la guía.

Fase 3. Activación del color dinámico

Theme.kt ya contenía la lógica pedida y se verificó sin modificarla: el parámetro dynamicColor vale true por defecto y la selección del esquema usa dynamicDarkColorScheme o dynamicLightColorScheme cuando Build.VERSION.SDK_INT >= Build.VERSION_CODES.S. En dispositivos anteriores a Android 12 se cae a LightColorScheme o DarkColorScheme, definidos con la paleta estática de Color.kt. El resultado se transmite a MaterialTheme junto con la nueva tipografía.

Fase 4. Pantalla ConfigScreen con TopAppBar

Se agregó ConfigScreen en MainActivity.kt. Su TopAppBar usa primaryContainer como fondo y onPrimaryContainer para el título, según la guía. Además de la frase de bienvenida, la pantalla muestra cinco bloques que pintan los roles primary, primaryContainer, secondaryContainer, tertiaryContainer y surfaceVariant con su color de contenido, para que el cambio de paleta sea visible de un vistazo. Para poder abrirla desde la aplicación se creó la ruta tipada ConfigRoute y se añadió un ícono de ajustes en la barra del formulario; el parámetro es opcional, por lo que las pruebas de resiliencia existentes no se ven afectadas.

Desafío extra. FloatingActionButton

Dentro del Scaffold de ConfigScreen se añadió un FloatingActionButton con containerColor = secondaryContainer. Se agregó también contentColor = onSecondaryContainer, porque al cambiar solo el fondo el ícono mantendría el color de contenido del rol anterior y podría perder contraste.

Resultados

Las pruebas se hicieron en el emulador Pixel 8 con Android 16 (API 36). Se generaron dos imágenes de fondo de pantalla, una degradada en naranja y otra en azul, y se aplicaron con la acción «Establecer como fondo» del sistema. Tras cada cambio se reinició la aplicación para leer el nuevo esquema.

La Figura 2 confirma el segundo resultado esperado de la guía: el TopAppBar, el FloatingActionButton y los textos cambian de tono sin tocar una sola línea de código. Con el fondo naranja la paleta es salmón y ámbar; con el azul, celeste y lavanda. La tipografía, en cambio, no depende del fondo: en ambas capturas los títulos se ven en Poppins Bold, con terminaciones redondeadas, que es el primer resultado esperado.

La Figura 3 muestra un beneficio adicional: como el tema es global, todas las pantallas previas de EcoTrip heredan la identidad visual (campos, chips, interruptores y botón de guardar) sin cambios individuales.

Influencia del colorScheme en la accesibilidad

El colorScheme es la capa donde se decide el contraste, y el contraste es la condición más básica de legibilidad para personas con baja visión, daltonismo o simplemente con la pantalla bajo el sol. El color dinámico introduce una incertidumbre nueva: el desarrollador ya no conoce de antemano los colores concretos. Material resuelve esto con roles emparejados cuyos tonos se calculan para garantizar una diferencia de luminosidad mínima (Google, s. f.-b), pero la garantía solo se cumple si el código respeta los pares. Poner texto onSurface sobre primaryContainer, o un color fijo como el negro sobre un fondo dinámico, rompe la garantía.

Para comprobarlo se midió el contraste real sobre las capturas de la Figura 2: se tomó el color del fondo de cada bloque y el píxel de texto más alejado de él, y se aplicó la fórmula de luminancia relativa de WCAG 2.2 (W3C, 2023). Como las capturas tienen suavizado de bordes, los valores son aproximaciones por defecto del contraste real.

Los cinco pares superan 4,5:1 con ambos fondos, y los valores son casi idénticos entre una paleta y otra (alrededor de 6:1), lo que ilustra la regularidad tonal del sistema. El margen más estrecho lo tiene surfaceVariant, el rol que se usa para texto secundario: por eso conviene no atenuarlo más con transparencia. Estos resultados se refieren al modo claro; el modo oscuro usa tonos distintos y debe verificarse por separado.

Otros dos aspectos del colorScheme afectan a la accesibilidad. Primero, el significado no debe depender solo del color: en la aplicación el estado «Activado/Desactivado» del resumen se expresa con texto, no únicamente con un tono. Segundo, la tipografía también cuenta: Poppins tiene aperturas amplias y buena altura de x, pero su peso Bold en 22 sp para títulos mantiene la jerarquía sin depender del color, y el cuerpo de 16 sp respeta el tamaño mínimo recomendado.

Dificultades encontradas

Tres situaciones merecen registro. (1) El proyecto no tenía font_certs.xml; sin él, Type.kt no compila porque R.array.com_google_android_gms_fonts_certs no existe. (2) La propiedad org.gradle.java.home del repositorio apunta a una ruta del equipo de otro integrante; en este equipo se compiló sustituyéndola por línea de comandos (JDK 21) sin modificar el archivo compartido. (3) La primera vez que se carga una fuente descargable el emulador necesita conexión a Internet y Google Play Services; la guía lo menciona como requisito previo y fue efectivamente necesario.

Conclusiones

El color dinámico logra que una aplicación se sienta parte del dispositivo con muy poco código: bastó con verificar una bandera y un bloque when en Theme.kt, y todas las pantallas de EcoTrip cambiaron de paleta a la vez. Lo que en realidad hace el trabajo es la disciplina de usar los roles del colorScheme en lugar de colores fijos, y esa disciplina es la que sostiene la accesibilidad: con cinco pares de roles y dos fondos muy distintos, el contraste se mantuvo entre 4,9:1 y 6,1:1, por encima del mínimo AA.

La tipografía aporta identidad con poco costo, pero introduce una dependencia de red y de Google Play Services. Mi valoración es que conviene aceptarla en aplicaciones con servicios de Google, y declarar una fuente de respaldo (la FontFamily por defecto) para dispositivos sin ellos. Además, aplicar Poppins solo a dos estilos, como sugiere la guía, habría dejado la aplicación con dos familias mezcladas; extenderla a toda la jerarquía fue una decisión que mejoró el resultado visual.

Por último, el laboratorio muestra que el diseño y la ingeniería no compiten: el mismo cambio que hizo la interfaz más moderna fue el que habría roto la legibilidad si se hubiera hecho sin respetar los pares de color. Medir el contraste, aun de forma aproximada, convirtió una afirmación de la teoría en un dato verificable.

Recomendaciones

1. Usar siempre pares de roles (x sobre onX) y evitar colores literales dentro de componentes; reservarlos para la paleta de respaldo.

2. Probar con al menos dos fondos muy distintos (uno claro y saturado, otro oscuro) y en modo claro y oscuro antes de dar por buena una pantalla.

3. Declarar una fuente de respaldo para dispositivos sin Google Play Services, por ejemplo con FontFamily(Font(googleFont = …), Font(DeviceFontFamilyName("sans-serif"))).

4. Automatizar la comprobación de contraste con el Escáner de Accesibilidad de Android o con pruebas de interfaz que inspeccionen el árbol semántico.

5. No fijar dynamicColor = true como única opción: ofrecer un ajuste para desactivarlo permite a una marca con colores obligatorios (por ejemplo, el verde de EcoTrip) conservar su identidad.

6. Mover el ajuste de color dinámico y el acceso a la pantalla de identidad a una pantalla de configuración definitiva antes de publicar la aplicación.

@OptIn(ExperimentalMaterial3Api::class)
@Composable
fun ConfigScreen(onVolver: (() -> Unit)? = null) {
    Scaffold(
        topBar = {
            TopAppBar(
                title = {
                    Text("EcoTrip 2026 - Identidad", style = MaterialTheme.typography.titleLarge)
                },
                navigationIcon = {
                    if (onVolver != null) {
                        IconButton(onClick = onVolver) {
                            Icon(
                                imageVector = Icons.AutoMirrored.Filled.ArrowBack,
                                contentDescription = "Volver al formulario"
                            )
                        }
                    }
                },
                colors = TopAppBarDefaults.topAppBarColors(
                    containerColor = MaterialTheme.colorScheme.primaryContainer,
                    titleContentColor = MaterialTheme.colorScheme.onPrimaryContainer,
                    navigationIconContentColor = MaterialTheme.colorScheme.onPrimaryContainer
                )
            )
        },
        floatingActionButton = {
            FloatingActionButton(
                onClick = { /* Acción */ },
                containerColor = MaterialTheme.colorScheme.secondaryContainer,
                contentColor = MaterialTheme.colorScheme.onSecondaryContainer
            ) {
                Icon(Icons.Default.Add, contentDescription = "Agregar")
            }
        }
    ) { innerPadding ->
        Column(
            modifier = Modifier
                .padding(innerPadding)
                .verticalScroll(rememberScrollState())
                .padding(16.dp),
            verticalArrangement = Arrangement.spacedBy(16.dp)
        ) {
            Text(
                text = "Bienvenido al futuro de la seguridad móvil.",
                style = MaterialTheme.typography.bodyLarge
            )
            Text(
                text = "Roles de color tomados del fondo de pantalla",
                style = MaterialTheme.typography.titleMedium
            )
            val colores = MaterialTheme.colorScheme
            ColorRole("primary", colores.primary, colores.onPrimary)
            ColorRole("primaryContainer", colores.primaryContainer, colores.onPrimaryContainer)
            ColorRole("secondaryContainer", colores.secondaryContainer, colores.onSecondaryContainer)
            ColorRole("tertiaryContainer", colores.tertiaryContainer, colores.onTertiaryContainer)
            ColorRole("surfaceVariant", colores.surfaceVariant, colores.onSurfaceVariant)
        }
    }
}

@Composable
private fun ColorRole(nombre: String, fondo: Color, contenido: Color) {
    Box(
        modifier = Modifier
            .fillMaxWidth()
            .height(56.dp)
            .background(fondo, RoundedCornerShape(16.dp))
            .padding(horizontal = 16.dp),
        contentAlignment = Alignment.CenterStart
    ) {
        Text(text = nombre, color = contenido, style = MaterialTheme.typography.bodyLarge)
    }
}

package com.example.myapplication.ui.theme

import android.app.Activity
import android.os.Build
import androidx.compose.foundation.isSystemInDarkTheme
import androidx.compose.material3.MaterialTheme
import androidx.compose.material3.darkColorScheme
import androidx.compose.material3.dynamicDarkColorScheme
import androidx.compose.material3.dynamicLightColorScheme
import androidx.compose.material3.lightColorScheme
import androidx.compose.runtime.Composable
import androidx.compose.ui.platform.LocalContext

private val DarkColorScheme = darkColorScheme(
    primary = Purple80,
    secondary = PurpleGrey80,
    tertiary = Pink80
)

private val LightColorScheme = lightColorScheme(
    primary = Purple40,
    secondary = PurpleGrey40,
    tertiary = Pink40

    /* Other default colors to override
    background = Color(0xFFFFFBFE),
    surface = Color(0xFFFFFBFE),
    onPrimary = Color.White,
    onSecondary = Color.White,
    onTertiary = Color.White,
    onBackground = Color(0xFF1C1B1F),
    onSurface = Color(0xFF1C1B1F),
    */
)

@Composable
fun MyApplicationTheme(
    darkTheme: Boolean = isSystemInDarkTheme(),
    // Dynamic color is available on Android 12+
    dynamicColor: Boolean = true,
    content: @Composable () -> Unit
) {
    val colorScheme = when {
        dynamicColor && Build.VERSION.SDK_INT >= Build.VERSION_CODES.S -> {
            val context = LocalContext.current
            if (darkTheme) dynamicDarkColorScheme(context) else dynamicLightColorScheme(context)
        }

        darkTheme -> DarkColorScheme
        else -> LightColorScheme
    }

    MaterialTheme(
        colorScheme = colorScheme,
        typography = Typography,
        content = content
    )
}

package com.example.myapplication.ui.theme

import androidx.compose.material3.Typography
import androidx.compose.ui.text.TextStyle
import androidx.compose.ui.text.font.FontFamily
import androidx.compose.ui.text.font.FontWeight
import androidx.compose.ui.text.googlefonts.Font
import androidx.compose.ui.text.googlefonts.GoogleFont
import androidx.compose.ui.unit.sp
import com.example.myapplication.R

// Proveedor de fuentes: Google Play Services descarga y cachea la fuente bajo demanda.
val provider = GoogleFont.Provider(
    providerAuthority = "com.google.android.gms.fonts",
    providerPackage = "com.google.android.gms",
    certificates = R.array.com_google_android_gms_fonts_certs
)

val fontName = GoogleFont("Poppins")

val poppinsFontFamily = FontFamily(
    Font(googleFont = fontName, fontProvider = provider, weight = FontWeight.Normal),
    Font(googleFont = fontName, fontProvider = provider, weight = FontWeight.Medium),
    Font(googleFont = fontName, fontProvider = provider, weight = FontWeight.SemiBold),
    Font(googleFont = fontName, fontProvider = provider, weight = FontWeight.Bold)
)

private val base = Typography()

// Poppins en toda la jerarquía de Material 3; titleLarge y bodyLarge fijan los valores del laboratorio.
val Typography = Typography(
    displayLarge = base.displayLarge.copy(fontFamily = poppinsFontFamily),
    displayMedium = base.displayMedium.copy(fontFamily = poppinsFontFamily),
    displaySmall = base.displaySmall.copy(fontFamily = poppinsFontFamily),
    headlineLarge = base.headlineLarge.copy(fontFamily = poppinsFontFamily),
    headlineMedium = base.headlineMedium.copy(fontFamily = poppinsFontFamily),
    headlineSmall = base.headlineSmall.copy(fontFamily = poppinsFontFamily),
    titleLarge = TextStyle(
        fontFamily = poppinsFontFamily,
        fontWeight = FontWeight.Bold,
        fontSize = 22.sp
    ),
    titleMedium = base.titleMedium.copy(fontFamily = poppinsFontFamily),
    titleSmall = base.titleSmall.copy(fontFamily = poppinsFontFamily),
    bodyLarge = TextStyle(
        fontFamily = poppinsFontFamily,
        fontWeight = FontWeight.Normal,
        fontSize = 16.sp
    ),
    bodyMedium = base.bodyMedium.copy(fontFamily = poppinsFontFamily),
    bodySmall = base.bodySmall.copy(fontFamily = poppinsFontFamily),
    labelLarge = base.labelLarge.copy(fontFamily = poppinsFontFamily),
    labelMedium = base.labelMedium.copy(fontFamily = poppinsFontFamily),
    labelSmall = base.labelSmall.copy(fontFamily = poppinsFontFamily)
)
